# 💜 WorkSpace 💜

**WorkSpace** — персональный веб-хаб для учебных заданий, лабораторных и практических работ. Проект помогает хранить учебные материалы в одном месте, быстро находить нужные работы и отслеживать собственный прогресс.

Сайт выполнен в тёмной фиолетовой теме. Вместо обычного списка файлов он предлагает удобный интерфейс, в котором учебные материалы организованы по предметам и лабораторным работам.

## 🌐 Живой сайт

**[Открыть WorkSpace](https://amagairei.github.io/WorkSpace/)**

**Исходный код проекта доступен в [репозитории на GitHub](https://github.com/AmagaiRei/WorkSpace).**

## 🎯 Цель проекта

Главная идея WorkSpace — собрать учебные работы в одном пространстве, чтобы не приходилось каждый раз искать нужный отчёт, архив или исходный код среди множества папок.

Проект создаётся как личный инструмент для организации учёбы, который можно постепенно развивать и адаптировать под собственные задачи.

## ✨ Возможности сайта

- 📚 **Предметы и лабораторные работы** — учебные материалы организованы по дисциплинам.
- 🔎 **Поиск** — помогает быстрее находить нужные материалы.
- 🏷️ **Фильтрация по тегам** — позволяет отбирать работы по указанным категориям.
- 📊 **Прогресс по предметам** — помогает отслеживать выполнение лабораторных работ.
- 🧪 **Страница лабораторной работы** — предоставляет доступ к связанным с ней материалам и файлам.
- 🚀 **Главный проект** — отдельный блок для представления основного проекта.
- 👤 **Контакты** — информация для связи с автором.
- 🌙 **Тёмная фиолетовая тема** — единый визуальный стиль интерфейса.

Предметы и лабораторные работы автоматически отображаются на сайте на основе данных из `data/subjects.json`. Благодаря этому добавление новых материалов не требует вручную создавать отдельную страницу для каждого предмета.

## 🛠️ Технологии

В проекте используются:

- **HTML5** — структура страниц.
- **CSS3** — оформление, адаптация интерфейса и визуальный стиль.
- **JavaScript (ES Modules)** — логика приложения, обработка данных и динамическое отображение содержимого.
- **JSON** — хранение информации о предметах и лабораторных работах.
- **Git и GitHub** — контроль версий и хранение исходного кода.
- **GitHub Pages** — публикация сайта в интернете.

Проект реализован на чистых HTML, CSS и JavaScript, без использования JavaScript-фреймворков.

## 📁 Структура проекта

Основные каталоги и файлы организованы следующим образом:

```text
WorkSpace/
├── index.html
├── data/
│   ├── subjects.json
│   └── labs/
│       └── <subjectId>/
│           └── lab-XX/
├── css/
│   └── ...
├── js/
│   └── ...
└── README.md
```

**Назначение основных элементов:**

- `index.html` — главная HTML-страница приложения.
- `data/subjects.json` — описание предметов и связанных с ними лабораторных работ.
- `data/labs/` — каталог с материалами лабораторных работ.
- `css/` — стили оформления сайта.
- `js/` — JavaScript-модули, отвечающие за работу интерфейса и обработку данных.
- `README.md` — описание проекта и инструкция по работе с ним.

> Структура показана в сокращённом виде. Многоточия обозначают дополнительные файлы и модули, которые могут присутствовать в проекте.

## 🧪 Как добавлять новые лабораторные работы

Новые лабораторные добавляются через каталог с данными и файл `data/subjects.json`.

### Шаг 1. Найди нужный предмет

Определи идентификатор предмета — `subjectId`. Он используется для организации файлов лабораторных.

### Шаг 2. Создай каталог лабораторной

Для каждой работы используется отдельная папка:

```text
data/labs/<subjectId>/lab-XX/
```

Например:

```text
data/labs/
└── programming/
    └── lab-01/
        ├── report.pdf
        ├── project.zip
        ├── src/
        └── screenshots/
```

В примере `programming` — идентификатор предмета, а `lab-01` — каталог первой лабораторной работы. Это пример организации файлов, а не обязательный перечень файлов для каждой работы.

В зависимости от конкретного задания лабораторная может содержать:

- 📄 **Отчёт** — например, `report.pdf` или `report.docx`.
- 📦 **Архив проекта** — например, `project.zip`.
- 💻 **Исходный код** — отдельные файлы или каталог с программой.
- 🖼️ **Скриншоты** — изображения результатов выполнения работы.

Необязательно добавлять все перечисленные материалы: состав зависит от содержания лабораторной.

### Шаг 3. Добавь информацию в `subjects.json`

В файле `data/subjects.json` необходимо описать новую лабораторную и связать её с соответствующим предметом.

После обновления данных сайт автоматически отображает предметы и лабораторные работы в интерфейсе.

При добавлении новой записи важно соблюдать существующую структуру JSON и использовать поля, предусмотренные текущей реализацией проекта.

### Шаг 4. Проверь результат

После добавления материалов:

1. Убедись, что JSON-файл содержит корректный синтаксис.
2. Проверь пути к отчётам, архивам и другим файлам.
3. Запусти сайт локально.
4. Убедись, что лабораторная отображается и её материалы открываются.
5. Проверь поиск, фильтры и прогресс по предмету.

### Шаг 5. Опубликуй изменения

Если всё работает корректно, сохрани изменения в Git и отправь их в репозиторий:

```bash
git add .
git commit -m "Add laboratory work"
git push
```

После публикации изменений GitHub Pages обновит сайт в соответствии с настройками развёртывания репозитория.

## 🗂️ Структура данных `subjects.json`

Файл `data/subjects.json` — основной источник данных для отображения учебных материалов.

В нём хранится информация о предметах и связанных с ними лабораторных работах. JavaScript использует эти данные, чтобы формировать содержимое страниц и отображать доступные материалы.

Основные задачи файла:

- определять список предметов;
- связывать лабораторные работы с соответствующими предметами;
- предоставлять данные, необходимые для отображения названий, описаний, тегов и другой информации, предусмотренной структурой проекта;
- обеспечивать автоматическое обновление отображаемого содержимого после изменения данных.

Пример условной структуры JSON:

```json
{
   "subjects": [
      {
         "id": "programming",
         "name": "Программирование",
         "labs": [
            {
               "id": "lab-01",
               "title": "Лабораторная работа № 1",
               "tags": []
            }
         ]
      }
   ]
}
```

Это **иллюстративный пример**, а не подтверждённая схема текущего файла. Перед добавлением записей необходимо сверяться с реальным содержимым `data/subjects.json`, поскольку приложение ожидает определённые названия полей и формат данных.

Рекомендуется придерживаться нескольких правил:

- сохранять уникальные идентификаторы предметов и лабораторных работ;
- соблюдать корректный синтаксис JSON;
- проверять пути к файлам;
- не менять структуру существующих записей без соответствующего обновления JavaScript-модулей.
